# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Marketing site for the BikeSpeed GPS speedometer app (iOS + Android, both v2.0), live at bikespeed.no. The apps live in separate repos, which are the source of truth for features, requirements and privacy behaviour (their READMEs are the quickest reference; `gh api repos/<repo>/readme -H "Accept: application/vnd.github.raw"`):

- iOS (Swift, iOS 18+): https://github.com/klekanger/BikeSpeed
- Android (Android 11+ with Google Play services): https://github.com/klekanger/BikeSpeed-Android

The two apps have the same features except sync: iOS mirrors the trip log to the user's private iCloud; Android stores rides on-device only. Platform data flows also differ (street-name lookups go to Apple on iOS and to Google's geocoder on Android; Android trip maps load Google Maps tiles), so site copy about storage, sync or privacy must cover both platforms.

## Commands

```bash
pnpm dev       # Vite dev server
pnpm build     # tsc type-check, then vite build to dist/
pnpm preview   # serve the production build
npx tsc --noEmit   # type-check only
```

There are no tests and no linter; `tsc` (with `noUnusedLocals`/`noUnusedParameters`) is the only check. Deployed on Vercel (the HTML loads `/_vercel/insights/script.js`).

## Architecture

Static multi-page Vite + TypeScript site, no framework. Each page is an HTML shell (`index.html`, `privacy.html`, `support.html`, all registered as inputs in `vite.config.ts`) with an empty `#app` and one entry script (`src/main.ts`, `src/privacy.ts`, `src/support.ts`).

**Rendering:** each entry builds its markup as a template string and passes it to `renderPage()` in `src/layout.ts`, which wraps it in the shared header/footer, wires up the language selector, applies translations, and starts the `[data-reveal]` scroll animations.

**i18n:** markup contains no copy. Elements carry `data-i18n="dot.path"` (sets textContent) or `data-i18n-attr="attr:dot.path;attr2:path2"` (sets attributes), resolved against `src/i18n/translations.ts`. Locales are `en` and `nb`; the `Dictionary` interface there must be updated whenever a key is added, and both locales filled in. `{year}`-style tokens are interpolated in `locale.ts`. Lists (features, highlights, FAQ) are generated by mapping over `translations.en.<list>` to emit indexed keys (`features.items.0.title`), so both locales must keep the same array lengths. The `<title>` and meta description in the HTML shells also use `data-i18n`.

**Locale switching:** `setLocale()` persists to `localStorage` (`bikespeed-locale`), re-applies translations, and dispatches a `bikespeed:localechange` event. Anything locale-specific that isn't text (localized screenshots under `public/screenshots/{en,nb}/`, App Store / Google Play badge images) is swapped by listeners for that event in `src/main.ts`; new localized assets need the same treatment.

**Gauge:** `src/gauge.ts` draws the hero SVG speedometer. Its constants deliberately mirror the app's `GaugeFaceView.swift` / `SpeedometerGaugeView.swift`; keep them in sync with the app rather than tweaking freely.

## Conventions

- Performance work is ongoing: fonts are self-hosted (`public/fonts/`, `@font-face` in `src/style.css`, preloaded in `index.html`), and images ship as downscaled WebP variants with explicit `width`/`height`. Screenshots use `-320`/`-560` variants via `srcset`; `SCREENSHOT_SIZES` in `main.ts` must match the gallery CSS.
- The hero store badges share `--cta-height` in `.hero-ctas`. GitHub repo links (open-source section, support page) come from `REPOS` / `renderRepoCards()` in `src/layout.ts`; the footer links use `REPOS` too.
- App version and platform info is hand-maintained in several places: the JSON-LD block and meta descriptions in `index.html`, `whatsNew`, `privacy` and `support` in `translations.ts`, and `README.md`.
- `support.html` has a JSON-LD `FAQPage` that duplicates `translations.en.support.faq`; update it whenever the English FAQ changes.
